## 1. 语音特征提取（code/audio/extract_audio_features.py）

按进度汇报约定：**16 kHz 重采样 → Wav2Vec2 时序特征 → 全局池化**，编码器全部冻结。

| 项目 | 设置 |
|---|---|
| 编码器 | `TencentGameMate/chinese-wav2vec2-base`（中文 WenetSpeech 预训练，94.4M 参数，hidden 768） |
| 输入 | mp4 → 16 kHz 单声道 float32；完整波形，不截断 |
| 预处理 | 该 checkpoint 的 feature extractor 为 `do_normalize=false`，直接输入原始波形，与预训练口径一致 |
| 前向 | `Wav2Vec2Model`，`eval()` + `requires_grad=False`；按最长波形 padding，带 attention mask，batch=16 |
| 池化 | 按 `conv_kernel/conv_stride` 推算各样本有效时序长度，对 `last_hidden_state` 做**时序均值池化**，d_a = 768 |
| 缓存 | `outputs/features/audio_cls.pt`（`feat / label3 / label_m / speech_frac / snr_db / rms_db / dur_sec`） |

- 全量提取约 **2 分钟**（GPU；逐条解码约 0.05 s，编码批处理占少数时间）。
- 加载时会出现 `quantizer.* / project_q.* / project_hid.*` 的 UNEXPECTED 键提示，这是
  Wav2Vec2 预训练阶段的量化头，`Wav2Vec2Model` 前向不使用，可忽略。
- 实现备注：在 valid 上比较过“逐句零均值单位方差归一化”和 VAD 加权 / 能量加权 / 高分位池化，
  均未带来稳定的 Macro-F1 提升，因此保留最简单、与预训练配置一致的“原始波形 + 时序均值”。
  所有选择只依据 valid，未用 test 调参。

### 质量信号（供后续质量门控，训练 / 评测 / 演示同口径）

以 25 ms 窗、10 ms 帧移计算帧级 RMS，取 10% 分位为噪声底、90% 分位为语音电平：

- **speech_frac**：RMS 高于 `噪声底 + 20% × (语音电平 − 噪声底)` 的帧比例，近似语音活动比例；
- **snr_db**：`20·log10(语音电平 / 噪声底)`，截断到 [0, 60] dB；
- **rms_db**：整段 RMS 电平。

三个量只依赖波形，不需要 ASR 或文本，演示时可与特征同步计算。

全量统计（train / valid / test 分布一致）：

| 划分 | 时长均值 | speech_frac 均值 / 中位 | SNR 中位 / p10–p90 | RMS 均值 |
|---|---|---|---|---|
| train | 3.70 s | 0.565 / 0.575 | 20.75 / 11.07–33.79 dB | −24.27 dB |
| valid | 3.61 s | 0.570 / 0.585 | 21.52 / 11.54–33.95 dB | −23.86 dB |
| test | 3.67 s | 0.573 / 0.583 | 21.15 / 11.43–34.31 dB | −23.68 dB |

## 2. 语音单模态基线（code/audio/train_audio_baseline.py）

与文本 / 视觉基线完全同一套协议：训练集标准化、768→256→3 MLP（dropout 0.3）、
类别加权交叉熵、Adam lr 1e-3 / wd 1e-4、按 valid Macro-F1 早停（patience 10）、seed 42；
另附同一特征、同一划分的 sklearn LogisticRegression（`class_weight='balanced'`）对照。

### 测试集结果（457 条）

| 模型 | Accuracy | Macro-F1 | Neg-F1 | Neu-F1 | Pos-F1 |
|---|---|---|---|---|---|
| MLP 头 | **0.4551** | **0.4114** | 0.5783 | 0.2995 | 0.3563 |
| LogisticRegression | 0.4748 | 0.4449 | 0.5695 | 0.3736 | 0.3916 |

MLP 混淆矩阵（行=真实 负/中/正）：

```
[[133,  70,  45],
 [ 20,  31,  18],
 [ 59,  37,  44]]
```

- 完整结果：`outputs/results/audio_baseline/audio_baseline_result.json`（含混淆矩阵 CSV）。
- MLP 最优 valid Macro-F1 = 0.3856（第 5 个 epoch 后早停），线上 test 0.4114；
  valid 与 test 都明显低于文本（0.5921）和视觉（0.5843）。
- 对照参考：全预测为多数类（负面）的 Accuracy = 0.5427，Macro-F1 = 0.2345。
  语音 MLP 的 Accuracy 低于多数类，但 Macro-F1 高 0.18，说明类别加权确实换来了中/正类的识别，
  不是纯粹的“退化分类器”。中性类仍最弱（F1 0.30）。
- 本次 LogisticRegression 反而优于 MLP（0.4449 vs 0.4114），且 valid 也更高（0.4210 vs 0.3856）：
  在 768 维冻结语音特征上，线性边界更稳，增加非线性容量没有收益。

### 质量信号诊断（仅描述，不参与训练）

在 test 上按 `speech_frac` 中位数二分：

| 子集 | Accuracy |
|---|---|
| speech_frac 低半 | 0.4803 |
| speech_frac 高半 | 0.4298 |

`speech_frac` 与是否预测正确的点二列相关为 **−0.0315**。即：在**干净测试集**上，
语音活动比例并不能解释对错，当前质量信号不具备“预测正确率”的能力。
这不等于质量门控无效——门控要处理的是**人为扰动的噪声/缺失**，该结论留待
“固定强度音频噪声”鲁棒性实验检验，不能据此预先宣称改进。

## 3. 当前进度对照（方案实验表“单模态”行）

| 模态 | 特征 | 缓存 | Acc | Macro-F1 |
|---|---|---|---|---|
| 文本 | bert-base-chinese [CLS] 768 | text_cls.pt | 0.6608 | 0.5921 |
| 视觉 | CLIP-ViT-B/32 [CLS] 512（T=8 平均） | vis_cls.pt | 0.6236 | 0.5843 |
| 语音 | chinese-wav2vec2-base 768（时序均值） | audio_cls.pt | 0.4551 | 0.4114 |

- 三路特征、缓存与单模态基线至此齐备，且共用同一 `sample_id`、同一官方划分。
- 语音单模态明显弱于另两路，可能原因：冻结 Wav2Vec2 以中文 ASR 为目标预训练，
  末层更偏语言内容而非韵律/情感；时序均值池化抹平了语调、能量变化；
  CH-SIMS 片段含背景音乐与影视混音；中性类只有 69 条 test 样本。
- 这与方案“冻结骨干、少做对照”的范围控制一致；不在本阶段引入微调或更大模型。
  融合阶段应关注：语音能否在文本/视觉之外提供互补信息，以及噪声条件下质量门控是否有效。
